## Interpretation Rules

- `Approved with Open Decisions` authorizes only the direction explicitly approved in the referenced ADR.
- Provider, shipping, pickup, tax, reservation, cancellation, refund, return, and go-live decisions remain open.
- The granular internal role model and matrix in `DEC-ACCESS-001` plus
  `DEC-ACCESS-002` are canonical. Proposed three-role documents and current
  runtime code do not override them.
- Manual transfer is not an open fallback: `DEC-PAY-02` limits it to read-only historical compatibility.
- Homepage pattern is resolved; detailed visual Retail/B2B navigation is not.
- The Admin Studio direction is approved as an experience decision, but no Admin implementation is authorized by this register.
- `DEC-AUTH-003` through `DEC-AUTH-010` approve only their bounded
  authentication directions; every listed open decision and implementation
  gate remains in force.
- `DEC-AUTH-006` amends the abuse-protection interface and privacy direction without replacing the topology and threshold deferrals in `DEC-AUTH-002`.
- `DEC-AUTH-008` requires the Admin help control to remain omitted until an existing internal destination and accountable owner are explicitly approved.
- `DEC-REMED-001` is the decision alias used by the Master Spec for `ADR-005`;
  they are one record, not two independent approvals. The following conflicts
  remain `Needs Clarification` and must not be silently resolved:
  `12–72 UTF-8 bytes` versus `15–128 Unicode code points plus 512 bytes`,
  universal seven-day refresh versus Admin default idle/eight-hour absolute
  lifetime, unified `{user}` refresh/logout wording versus the Admin
  synchronizer-CSRF session surface, and whether cursor pagination extends
  beyond the explicitly named public catalog.
- When this register summarizes an ADR, the ADR remains the technical authority.
- Decision records do not override an approved requirement outside their stated scope.
