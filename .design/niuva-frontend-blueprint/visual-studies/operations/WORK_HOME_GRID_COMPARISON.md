# OPS-08 Operations Work-Home Grid Comparison

**Status:** Candidate — Context Only — LOCAL Operations study; no shared token,
metric, data, primitive, or source change

## 1. Alternatives

### A — Priority column (preferred)

One primary work column ordered by role/age/exception, with a secondary
context rail for authorized summaries. This supports scan order without making
each module a decorative card.

### B — Bounded unequal grid (held)

An unequal grid may place a factual queue beside a smaller exception/context
module when real work evidence justifies it. Modules retain source, owner, and
next action; no equal bento tiles or fake KPI values.

## 2. Comparison

| Check | A priority column | B unequal grid |
| --- | --- | --- |
| Scan order | Explicit and linear | Requires stronger role evidence |
| Density | Predictable queue/detail handoff | Better for proven parallel work |
| Responsive | Stacks naturally at 390px | Requires careful order/reflow |
| Keyboard | Simple deterministic order | Must preserve source order across tracks |
| Risk | Low visual novelty | Can drift into bento/dashboard decoration |

## 3. States and boundary

Both alternatives must represent loading, empty, error, permission, conflict,
and recovery; a module cannot transfer to a queue/detail/form without an
authorized action. No fake KPI, telemetry, or Public campaign composition.

Passed Product-register, OPS-02, DS-04/DS-05, 390/768/1024/1440, 200%,
keyboard-order, and logo-hidden checks. A is preferred for lower density risk;
